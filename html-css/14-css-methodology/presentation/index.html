Знайома ситуація?

                .menu a { color: #333; }
                .header .menu li a { color: blue; }
                #nav .menu li a { color: green; }
                .footer a { color: #333 !important; }
                .menu a.link { color: red !important; }

Кожен новий стиль «перебиває» попередній — специфічність тільки росте, а !important множиться.

Проблеми CSS без правил

  • Глобальність: будь-який клас діє на всю сторінку — стилі одного компонента «ламають» інший.
  • Війна специфічності: .header .menu li a → #nav .menu li a → !important → …
  • Страх видаляти: «а раптом цей клас ще десь використовується?» — CSS лише росте.
  • Неочевидні зв'язки: з HTML не зрозуміло, де лежать стилі і що від чого залежить.
  • Залежність від DOM: переніс блок в інше місце — він виглядає інакше.

Що таке CSS-методологія

CSS-методологія — набір правил і домовленостей щодо іменування класів та організації файлів стилів.

BEM: Block, Element, Modifier

Найпопулярніша методологія іменування (2009). Інтерфейс ділиться на незалежні блоки.

            block
            block__element
            block--modifier
            block__element--modifier
        
            .search-form
            .search-form__input
            .search-form--compact
            .search-form__button--disabled

Слова всередині назви — через дефіс: search-form. Два підкреслення __ — елемент, два дефіси -- — модифікатор.

Блок, елемент, модифікатор

Сутність Що це Питання Приклади
Block Незалежний компонент, має сенс сам по собі «Що це?» header, menu, card
Element Частина блоку, окремо не існує «Що це?» menu__item, card__title
Modifier Стан, вигляд або поведінка «Який? Як поводиться?» button--disabled, card--featured

Назви — за змістом, а не за виглядом: ✅ button--danger   ❌ button--red   ❌ big-block

BEM на прикладі картки

        <article class="card card--featured">
          <img class="card__img" src="pug.png" alt="Pug">
          <h3 class="card__title">Pug</h3>
          <p class="card__text">Шаблонізатор для HTML</p>
          <a class="card__btn button button--primary" href="#">Детальніше</a>
        </article>
    
        .card { padding: 16px; border-radius: 12px; }
        .card--featured { border: 2px solid gold; }
        .card__img { width: 100%; }
        .card__title { font-size: 1.25rem; }

Правила BEM

  • ✅ Стилізуємо лише через класи — не теги, не id.
  • ✅ Специфічність усіх селекторів однакова (0,1,0) → жодних воєн специфічності.
  • ❌ Не відображаємо вкладеність DOM у назві: card__body__title → card__title. Елемент належить блоку, а не іншому елементу.
  • ✅ Модифікатор завжди разом з основним класом: class="button button--primary".
  • ✅ Блок не задає собі зовнішніх відступів і позиції — це робить батьківський блок.

Міксування (mix)

Один HTML-вузол може бути одночасно елементом одного блоку і самостійним блоком.

        <a class="card__btn button button--primary" href="#">Детальніше</a>
    
        /* блок button: як виглядає кнопка будь-де */
        .button { padding: 8px 16px; border-radius: 6px; }
        .button--primary { background: #4b86c2; color: #fff; }
         
        /* елемент card__btn: де кнопка стоїть усередині картки */
        .card__btn { margin-top: auto; align-self: flex-start; }

BEM + SCSS

            .card {
              padding: 16px;
             
              &__title { font-size: 1.25rem; }
              &__img   { width: 100%; }
             
              &--featured {
                border: 2px solid gold;
              }
            }
        
            /* результат компіляції */
            .card { padding: 16px; }
            .card__title {
              font-size: 1.25rem;
            }
            .card__img { width: 100%; }
            .card--featured {
              border: 2px solid gold;
            }

Один блок = один файл: components/_card.scss. & склеює назву, але не створює вкладеності.

BEM: переваги та недоліки

✅ Переваги ❌ Недоліки
Ідеально для компонентного підходу Довгі назви класів
Структура зрозуміла з HTML Потрібна дисципліна команди
Плоска специфічність Спочатку здається «багатослівним»
Блоки легко переносити й видаляти Не регулює структуру файлів

OOCSS: структура окремо від оформлення

Object-Oriented CSS — Nicole Sullivan, 2008. Ідея з ООП: перевикористовувані CSS-«об'єкти».

            /* ❌ усе змішано, дублювання */
            .btn-login {
              padding: 8px 16px;
              border-radius: 4px;
              background: blue;
            }
            .btn-delete {
              padding: 8px 16px;
              border-radius: 4px;
              background: red;
            }
        
            /* ✅ structure + skin */
            .btn {
              padding: 8px 16px;
              border-radius: 4px;
            }
            .skin-primary { background: blue; }
            .skin-danger  { background: red; }
             
            <button class="btn skin-danger">

OOCSS: вміст окремо від контейнера

            /* ❌ залежить від місця */
            .sidebar h3 {
              font-size: 18px;
            }
            .footer h3 {
              font-size: 18px;
            }
        
            /* ✅ виглядає однаково будь-де */
            .heading-small {
              font-size: 18px;
            }
✅ Переваги ❌ Недоліки
Гнучкі, перевикористовувані компоненти, менше дублювання Багато класів в HTML, немає правил іменування → «зоопарк» класів

SMACSS: 5 категорій стилів

Scalable and Modular Architecture for CSS — Jonathan Snook, 2011.

Категорія Що містить Приклад
Base Нормалізація, стилі за замовчуванням — лише теги body, a, h1 { … }
Layout Великі секції сторінки, префікс l- .l-header, .l-sidebar
Module Перевикористовувані компоненти .nav, .card
State Стани, префікси is-, has- .is-active, .has-error
Theme Тема оформлення theme-dark.css

SMACSS на практиці

        <header class="l-header">
          <nav class="nav">
            <a class="nav__link is-active" href="#">Головна</a>
          </nav>
        </header>
  • ✅ Логічний поділ CSS на файли, гнучкість під різні проєкти.
  • ❌ Дозволяє id для лейаутів і ланцюжки селекторів для станів (.nav .is-active) — специфічність знову росте.
  • 💡 Префікси станів is- / has- широко використовують разом із BEM, особливо для станів, які перемикає JavaScript.

Inverted Triangle CSS — Harry Roberts.

Згори вниз:

  • охоплення: широке → вузьке
  • специфічність: низька → висока
  • явність: загальне → конкретне

Settings і Tools не генерують жодного CSS.

ITCSS у проєкті

            scss/
            ├── settings/   _colors.scss
            ├── tools/      _mixins.scss
            ├── generic/    _reset.scss
            ├── elements/   _typography.scss
            ├── objects/    _container.scss
            ├── components/ _card.scss
            │               _button.scss
            ├── utilities/  _helpers.scss
            └── main.scss
        
            // main.scss — порядок = шари
            @use 'settings/colors';
            @use 'tools/mixins';
            @use 'generic/reset';
            @use 'elements/typography';
            @use 'objects/container';
            @use 'components/card';
            @use 'components/button';
            @use 'utilities/helpers';

Кожен наступний шар лише доповнює попередні — правила перекриваються природним шляхом, без !important-воєн.

Нативний аналог: каскадні шари @layer

        /* оголошуємо порядок шарів один раз */
        @layer reset, base, components, utilities;
         
        @layer components {
          #promo .card .title { color: navy; }   /* (1,2,0) */
        }
         
        @layer utilities {
          .text-red { color: red; }              /* (0,1,0) — але перемагає! */
        }

Шар, оголошений пізніше, перемагає незалежно від специфічності. Підтримка — усі сучасні браузери (з 2022).

@layer: як браузер обирає переможця

Каскад перевіряє критерії по черзі — наступний лише тоді, коли попередній дав нічию:

  1. Походження та !important
  2. Шар (@layer) ← нове
  3. Специфічність
  4. Порядок у коді

Тобто шари стоять вище за специфічність: порівнювати селектори з різних шарів навіть не доводиться.

Три правила, які варто запам'ятати:

  • Пізніший шар перемагає ранній.
  • Стилі поза будь-яким шаром перемагають усі шари.
  • З !important порядок інвертується: важливе правило з раннього шару сильніше за важливе з пізнього.

@layer: стилі поза шарами та !important

            @layer base, components;
             
            @layer components {
              .btn { color: white; }
            }
             
            /* поза шаром — перемагає */
            a { color: blue; }
             
            /* <a class="btn"> → blue */
        
            @layer base, components;
             
            @layer base {
              a { color: black !important; }
            }
            @layer components {
              .btn { color: red !important; }
            }
             
            /* <a class="btn"> → black */

Логіка: ранні шари (reset, base) задають «фундамент», і якщо вони кажуть !important — пізніші шари не мають права це зламати.

@layer: способи оголошення

            /* 1. Лише порядок (інструкція) */
            @layer reset, base, components;
             
            /* 2. Блок із правилами */
            @layer base {
              body { margin: 0; }
            }
             
            /* 3. Дописати в той самий шар
                  (в іншому місці / файлі) */
            @layer base {
              a { color: inherit; }
            }
        
            /* 4. Імпорт файлу одразу в шар */
            @import url("reset.css") layer(reset);
             
            /* 5. Анонімний шар — не можна
                  доповнити пізніше */
            @layer {
              .tmp { outline: 1px solid red; }
            }
             
            /* 6. Імпорт у шар + медіазапит */
            @import url("print.css") layer(print) print;

Порядок шарів фіксується при першій появі назви. Тому інструкцію @layer a, b, c; ставлять на самий початок головного файлу.

Вкладені шари та сторонні бібліотеки

            /* бібліотеку — у найнижчий шар */
            @layer vendor, base, components;
             
            @import url("bootstrap.css")
                    layer(vendor);
             
            @layer components {
              /* (0,1,0) перебиває будь-який
                 селектор Bootstrap */
              .btn { border-radius: 0; }
            }
        
            /* вкладені шари */
            @layer components {
              @layer card, button;
              @layer card { .card { … } }
            }
             
            /* звернення через крапку */
            @layer components.button {
              .button { … }
            }

Головний практичний виграш: стилі UI-бібліотеки більше не змушують писати !important чи «прокачувати» специфічність, щоб їх перевизначити.

ITCSS → @layer: повна картина

            /* main.css */
            @layer generic, elements, objects,
                   components, utilities;
             
            @import url("generic/reset.css")  layer(generic);
            @import url("elements/type.css")  layer(elements);
            @import url("objects/grid.css")   layer(objects);
            @import url("components/card.css")
                                     layer(components);
            @import url("utilities/text.css") layer(utilities);
  • Settings → CSS custom properties у :root (шар не потрібен).
  • Порядок шарів тепер гарантує браузер, а не дисципліна команди чи порядок @use.
  • Utilities перемагають без !important.
  • Tailwind v4 сам генерує @layer theme, base, components, utilities.

Atomic CSS: один клас — одна властивість

            .flex        { display: flex; }
            .items-center{ align-items: center; }
            .p-4         { padding: 1rem; }
            .text-center { text-align: center; }
            .bg-white    { background: #fff; }
            .rounded-lg  { border-radius: .5rem; }

Замість «назвати компонент і описати його в CSS» — збираємо вигляд прямо в HTML з готових «атомів».

Найвідоміша реалізація — Tailwind CSS: генерує лише ті утиліти, що реально використані в розмітці.

Tailwind CSS

        <div class="flex items-center justify-between p-4 bg-white rounded-lg shadow">
          <h3 class="text-lg font-bold text-gray-900">Pug</h3>
          <a class="px-4 py-2 bg-blue-500 text-white rounded hover:bg-blue-600 md:px-6">Більше</a>
        </div>

Наш курс

BEM обов'язково + SCSS-partials за шарами ITCSS

Сучасний CSS допомагає методологіям

  • Нативна вкладеність (CSS Nesting) — як у SCSS, але без компіляції: .card { &:hover { … } }
  • @layer — порядок шарів замість війни специфічності (ідея ITCSS).
  • @scope — обмежує стилі піддеревом DOM: @scope (.card) { img { … } }
  • Custom properties — теми й модифікатори через змінні: .button--danger { --btn-bg: red; }
  • :where() — селектор з нульовою специфічністю, зручний для base-стилів.

Інструменти змінюються, а принципи (низька специфічність, незалежні компоненти, передбачуваний порядок) — лишаються.

Кроки 1–3: план, середовище, HTML

  • Аналіз макета (Figma): визначте блоки та компоненти, що повторюються, палітру, шрифти, відступи, breakpoints.
  • 💡 Лайфхак: роздрукуйте або зробіть скріншот макета й обведіть блоки з BEM-назвами — структура видна ще до першого рядка коду.
  • Середовище: scss/, js/, images/, fonts/; index.html, normalize; Git з першого дня; Vite / Gulp.
  • HTML: семантика (header, main, section, footer) + BEM-класи; компоненти — окремі Pug-partials.

Кроки 4–7: стилі шар за шаром

  • 4. Reset + змінні: normalize, box-sizing, кольори/шрифти/breakpoints у settings.
  • 5. Глобальні стилі: body, h1–h6, a, .container.
  • 6. Компоненти: спершу header, footer, навігація, далі картки, кнопки, форми.
  • 7. Контент: секції сторінки з готових компонентів.
            .card {
              display: grid;
              gap: 12px;
             
              @media (min-width: 768px) {
                grid-template-columns: 1fr 2fr;
              }
            }

Медіазапити пишемо одразу в компоненті, а не окремим файлом «в кінці».

Кроки 8–9: тестування та оптимізація

8. Тестування

9. Оптимізація

  • Зображення: WebP / AVIF, loading="lazy"
  • Lighthouse, PageSpeed Insights
  • Мініфікація CSS, видалення невикористаних стилів

✅ Чек-лист перед здачею проєкту

  • Валідний HTML (0 помилок)
  • Семантичні теги, один <h1>, alt у зображень
  • Класи за BEM
  • Немає стилів за id та !important
  • box-sizing: border-box
  • Адаптивність 320–1920px без горизонтальної прокрутки
  • Працює в Chrome, Firefox, Safari
  • Видимий :focus, навігація з клавіатури
  • Оптимізовані зображення, loading="lazy"
  • Lighthouse ≥ 90
