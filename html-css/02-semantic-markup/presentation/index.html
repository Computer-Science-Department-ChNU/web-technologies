Структура сучасного HTML5-документа

HTML - HyperText Markup Language

Мова для створення розмітки документів, з яких складаються вебсторінки в браузері з метою забезпечення їх простоти. Всі вебсторінки складаються з html елементів, які формують їх.

HTML файл може бути створений та відредагований у будь-якому текстовому редакторі або IDE.

Структура сучасного HTML5-документа

Елементами header є заголовки розділів. Вони можуть складатися з декількох частин — наприклад, було б виправдано розділяти блок заголовка на підзаголовки, історію версій або вказання авторства. Елемент footer визначає нижню частину розділу, до якого він відноситься. Зазвичай він містить інформацію про розділ — наприклад, ім'я автора, посилання на схожі документи, копірайт і тому подібне. Блок nav містить список посилань для навігації. Підходить, наприклад, для навігації по сайту, або для змісту. Елемент aside підходить для розміщення вмісту яким-небудь чином спорідненого основному контенту. У звичайному випадку буде корисний для розмітки бічної колонки. Тег section представляє загальний розділ документа або додатку, наприклад, такий як розділ. Тег article відзначає незалежний розділ документа, сторінки або сайту. Застосуємо для такого вмісту як новини, запису блога, повідомлення у форумі або коментарі користувачів.

Структура сучасного HTML5-документа

Тег <html> є контейнером, який містить у собі весь вміст веб-сторінки, включаючи теги <head> та <body>. Відкриває та закриває теги <html> у документі необов'язкові, але гарний стиль диктує неодмінне їх використання.
Тег <head> містить інформацію про сторінку. У ньому розташовуються метатеги, посилання на модулі, що підключаються.
Тег <body> є контейнером для всього вмісту, яке буде відображено користувачеві.

Специфіка директиви DOCTYPE

Навіщо потрібен DOCTYPE?

  • Повідомляє браузеру, за якою специфікацією обробляти документ
  • Вмикає Standards mode (режим стандартів) замість Quirks mode (режим сумісності)
  • У Quirks mode браузер емулює застарілу, непослідовну поведінку рендерингу 1990-х років (інша box-модель, інша обробка відсотків тощо)
  • Відсутній або неправильний DOCTYPE - непередбачувана поведінка CSS-верстки

Блочні та рядкові елементи

Блочні елементи займають всю доступну їм ширину і висота елемента визначається його вмістом (текст або інший вкладений елемент). Такі елементи розміщуються на окремому рядку.

Рядкові елементи - це теги, які поводяться подібно до звичайного тексту і цілком можуть бути розміщені всередині блокового елемента. В основному призначені для того, щоб змінити зовнішній вигляд тексту

Основні складові тегу

  1. Тег. У елементів, які мають вміст, їх зазвичай два – відкриває та закриває.
  2. Атрибут. Атрибут містить певну інформацію щодо елемента. В одного елемента їх може бути кілька, а може й не бути.
  3. Значення атрибута.
  4. Вміст елемента.
  5. Елемент. Його межі описуються відкриваючим та закриваючим тегами.

Основні правила розмітки

  1. Елементи не повинні перетинатись. Іншими словами, якщо тег, що відкриває розташовується всередині елемента, то й відповідний закриваючий тег повинен розташовуватися всередині цього елемента.
  2. Блочні елементи можуть містити текстові елементи, а також вкладені блокові.
  3. Строкові елементи можуть містити вкладені текстові елементи.
  4. Строкові елементи не можуть містити вкладені блокові елементи

Семантична карта тегів HTML5

Навіщо потрібна семантична розмітка

  • Доступність - screen reader'и коректно озвучують структуру сторінки для людей з порушеннями зору
  • SEO - пошукові роботи краще розуміють ієрархію та значущість контенту
  • Підтримка коду - роль блока одразу зрозуміла (<header>,
    а не <div class="header">)
  • Чистота коду - менше зайвих класів-хуків лише заради стилізації/скриптів

Семантична карта тегів HTML5

Структурні розділи сторінки

  • <header> - шапка сторінки або секції (логотип, заголовок, часто навігація)
  • <nav> - блок навігаційних посилань
  • <main> - основний унікальний контент сторінки (лише один на документ)
  • <article> - самодостатній, незалежний блок контенту (стаття, пост, коментар)
  • <section> - тематично згрупована частина контенту з власним заголовком
  • <aside> - побічний контент (сайдбар, врізка, реклама)
  • <footer> - підвал сторінки або секції (контакти, копірайт)

Семантична карта тегів HTML5

Семантика текстового контенту

  • <h1 - h6> - заголовки з ієрархією важливості
  • <p> - абзац тексту
  • <blockquote / q> - блокова та рядкова цитата
  • <strong / em> - семантичне (а не лише візуальне) виділення важливості/наголосу
  • <mark> - виділення релевантного фрагмента (наприклад, результат пошуку)
  • <time datetime="..."> - машинозчитувана дата/час

Семантична карта тегів HTML5

Семантика списків

  • <ul> - неупорядкований список (>li>)
  • <ol> -упорядкований список (>li>) + атрибути start, reversed, type
  • <dl> / <dt> / <dd> - список визначень

Впорядковані списки (ordered list - ol)

Тег <ol></ol> є контейнером для впорядкованих списків, так і розшифровується – ordered list. Усі елементи списку розміщують усередині тегів <li>...</li>, які у свою чергу поміщаються у загальний контейнер <ol></ol>.

Атрибут type у впорядкованих списках

Усі списки мають атрибут type, який вказує тип маркера. Впорядковані списки можуть приймати такі значення:

  1. A – вказує на те, що пункти списку нумеруватимуться великими латинські літери.
  2. a – вказує на те, що пункти списку нумеруватимуться маленькими латинські літери.
  3. I – вказує на те, що пункти списку нумеруватимуться великими римськими цифрами.
  4. i – вказує на те, що пункти списку нумеруватимуться маленькими римськими цифрами.

Невпорядковані списки (unordered list - ul)

Тег <ul></ul> є контейнером для неупорядкованих списків, так і розшифровується – unordered list. Усі елементи списку полягають усередині тегів <li></li> , які у свою чергу поміщаються у загальний контейнер <ul></ul> .

Code example unordered list

Атрибут type у неупорядкованих списках

Усі списки мають атрибут type, який вказує тип маркера. У невпорядкованих списків може приймати такі значення:

  1. disc – вказує маркер у вигляді чорного зафарбованого кола.
  2. circle – вказує маркер у вигляді порожнього кола.
  3. square – вказує маркер у вигляді чорного зафарбованого квадрата.
  4. none - Вказує, що список необхідно реалізувати без маркера.
  5. Свій маркер можна встановити вказавши в атрибуті style властивість list-styleimage:url(), вказавши в ньому адресу зображення, яке буде використане в як маркера.

Вкладені списки (nested lists)

У елементи списку можна вкладати не лише текстовий вміст, а й інші списки. Таким чином будуть реалізовані вкладені списки, а точніше підписки.

При цьому за умовчанням у вкладених списках маркер буде відмінним від маркера головного список.

Списки визначень (definition term)

Існують спеціальні списки для визначень, для цього слід використовувати контейнер <dl>...</dl>. Елементи таких списків складаються з двох складових: перша – це сам термін, укладений у тег <dt>...</dt>, другий – саме визначення, вкладене у тег <dd>...</dd>.

Семантична карта тегів HTML5

Семантика таблиць

  • <table> - контейнер табличних даних
  • <caption> - заголовок таблиці
  • <thead> / <tbody> / <tfoot> - логічні групи рядків

Створення таблиці

Тег <table>є основним контейнером, у який поміщається таблиця. Саме у ньому вказуються всі атрибути для таблиці та розміщується вся розмітка таблиці.

Таблиця часто використовується для візуалізації табличних даних, а також застосовується для реалізації верстки певних сторінок.

Іноді весь каркас сторінки будується за допомогою таблиць, але останнім часом ця техніка застосовується рідко.

<th>...</th> - тег, який описує спеціальний вид комірок, заголовних комірок. При цьому текст усередині цих клітинок вважається більш важливим, ніж простих, і набуває особливих властивостей - текст центрується та отримує напівжирне накреслення:

Назва таблиці, тег <caption>

Тег <caption></caption> - назва таблиці, яка розміщується зверху над таблицею і вирівнюється по центру. Сам тег слід розмістити одразу після відкриваючого тега <table>.

Порожні комірки

Не слід залишати порожні комірки, оскільки в деяких браузерах вони будуть відображені некоректно і згодом вплинуть на візуалізацію всієї таблиці. Якщо Вам справді необхідно залишити їх порожніми, розмістіть там пробіл, вказавши його код &nbsp;

Empty cells code example
(англ. non-breaking space) - символ нерозривного пробілу в тексті. На відміну від звичайного пробілу   не дає браузеру розривати рядок у місці, де розташований. Служить для поліпшення читабельності тексту.

Атрибути тегу <table>

Тег <table>, як і інші теги, має свої особливі атрибути:

  1. border - рамка таблиці, як навколо неї, так і всередині між комірками.
  2. cellpadding - відступи всередині комірок.
  3. cellspacing - відступи всередині таблиці між комірками і до меж таблиці.
  4. bgcolor та background - колір фону таблиці та зображення, яке буде використано як фон таблиці.
  5. align - визначає горизонтальне вирівнювання вмісту.

Атрибут cellspacing

Атрибут таблиці cellspacing говорить про відступи між комірками таблиці та відступи від меж комірок до меж самої таблиці.

Атрибут cellpadding

Атрибут таблиці cellpadding говорить про відступи всередині комірок, тобто відступи від меж комірок до вмісту.

Атрибут colspan

Атрибут таблиці colspan визначає об'єднання стовпців у один рядок. Значення атрибута вказує на те, скільки стовпчиків буде об'єднано..

Атрибут rowspan

Атрибут rowspan встановлює число клітинок, які мають бути об'єднані по вертикалі. Цей атрибут має сенс для таблиць, що складаються з декількох рядків.

<a href="url_path" _target="" rel="" title="">

Абсолютний шлях - https://example.ua/". Відносний шлях – вказує шлях щодо поточного файлу. Відносний шлях виглядає так: директорія(точне ім'я)/файл(з розширенням)

Позначення щодо відносного маршруту:
  • / - корінь, для сторінок це головна;
  • ./ - вказує поточну папку, де знаходиться файл;
  • ../ - піднятися на один рівень вище щодо поточної папки (вийти з папки).

Валідація HTML коду

Валідний код html - це написаний код відповідно до всіх рекомендацій специфікації консорціуму W3C. Валідація необхідна для пошукових роботів, оскільки вони працюють за стандартами і при грубих помилках розпізнавання контенту на сайті буде некоректним і вплине на видачу сторінки під час її пошуку.

https://validator.w3.org/ - сторінка для перевірки валідності html коду

Помилки валідації не завжди «ламають» рендеринг у браузері, але вказують на потенційні проблеми сумісності та доступності

Автоматизована перевірка в розробці

  • Лінтери: HTMLHint, markuplint - перевірка синтаксису й стилю під час розробки
  • CI/CD: автоматичний запуск валідатора на кожен pull request
  • Lighthouse (Chrome DevTools) - аудит доступності, SEO, продуктивності поряд з базовою перевіркою розмітки
  • IDE-плагіни (наприклад, W3C Web Validator для VS Code) - перевірка в реальному часі під час написання коду

Підсумки

  • HTML5-документ має чітку структуру: DOCTYPE - html - head/body
  • DOCTYPE вмикає режим стандартів і відрізняється спрощеним синтаксисом порівняно з HTML 4.01/XHTML
  • Block та inline elements - це передусім CSS-модель відображення, що модифікується сучасними display-значеннями
  • Метатеги впливають на SEO та на вигляд посилання в соцмережах через Open Graph
  • Семантичні теги HTML5 покращують доступність, SEO та підтримуваність коду
  • Валідність коду перевіряється за стандартами W3C вручну та автоматизовано в CI/CD
