= ЛАБОРАТОРНА РОБОТА №10

*Тема: CSS-методології та робочий процес верстки.
Фінальний проєкт: адаптивний лендінг за макетом Figma.*

*Мета: Закріпити й застосувати в комплексі всі знання курсу: семантичну розмітку, доступність, CSS Grid і Flexbox, адаптивну верстку mobile first, препроцесори та автоматизацію збирання.
Навчитися організовувати стилі проєкту за CSS-методологіями (BEM у поєднанні з SMACSS, ITCSS або каскадними шарами `@layer`), реалізовувати модульну сітку макета, дотримуватися pixel perfect-точності, а також контролювати якість результату: валідність, продуктивність, доступність і SEO.*

*Вимоги до звіту:*

. Роботу виконувати у `НОВОМУ` репозиторію з назвою `landing-<бренд>` (`landing-bang-olufsen`, `landing-nothing`, `landing-bose`).
. Основа - збірка на Vite, Pug і SCSS, налаштована в link:../lab-09/lab-09.adoc[лабораторній роботі №9]: PostCSS (Autoprefixer + Browserslist), оптимізація зображень, Prettier, Stylelint, husky і lint-staged.
. Робота виконується *без JavaScript*: у `dist/index.html` не має бути жодного власного скрипта (бандл Vite, що підключає лише стилі, - допускається).
. Заборонено використання фреймворків та сторонніх UI-бібліотек (Bootstrap, Tailwind тощо).
. Дотримуватись правил написання html, css та правил іменування файлів.
. Історія комітів має відображати хід роботи (не один коміт «done» наприкінці); повідомлення - за https://www.conventionalcommits.org/uk/v1.0.0/[Conventional Commits].

[WARNING]
====
Верстка повинна *відповідати макету*: зображення, іконки, логотип, шрифти, кольори, розміри, відступи, стани елементів.
Роботу із заміненими зображеннями, «схожими» іконками чи шрифтами, іншою сіткою або пропущеними станами *не буде зараховано*.
====

Однакові за виглядом елементи - це *один блок* з модифікаторами, а не кілька різних.

** шрифти - підключити *саме ті*, що в макеті (Google Fonts або локальні WOFF2 з `@font-face` і `font-display: swap`), лише потрібні накреслення.

=== Завдання 2. Архітектура стилів за методологією

Іменування класів у всіх варіантах - *BEM* (`block`, `block__element`, `block--modifier`, `block__element--modifier`).
Один BEM-блок - один SCSS-partial.
Організація файлів і порядок каскаду - за методологією свого варіанта.

==== Варіант 1. BEM + SMACSS

.Структура стилів
----
src/styles/
├── abstracts/      # змінні, функції, міксини - не генерують CSS
├── base/           # reset/normalize, html, body, типографіка, @font-face (лише селектори елементів)
├── layout/         # l-container, l-grid, l-header, l-footer - великі області сторінки
├── modules/        # BEM-блоки: product-card, category, button, field, contacts ...
├── state/          # is-open, is-active, is-hidden ... (стани)
├── theme/          # (за потреби) кольорові теми, custom properties
└── main.scss
----

* Класи layout - з префіксом `l-` (`.l-container`, `.l-grid`), стани - з префіксом `is-` / `has-` (`.is-open`).
* Стани, що залежать від модуля, допускається описувати в самому модулі (`.nav.is-open`), глобальні - у `state/`.
* У `base/` - *жодного класу*.

==== Варіант 2. BEM + ITCSS

.Структура стилів (від загального до конкретного)
----
src/styles/
├── 1-settings/     # змінні, токени, map-и брейкпоінтів
├── 2-tools/        # міксини, функції
├── 3-generic/      # reset/normalize, box-sizing
├── 4-elements/     # стилі HTML-елементів без класів (h1-h6, a, img, body)
├── 5-objects/      # o-container, o-grid, o-media - структура без оформлення
├── 6-components/   # c-header, c-product-card, c-button ... - BEM-блоки
├── 7-utilities/    # u-visually-hidden, u-text-center ... (допускається !important)
└── main.scss
----

* Префікси за шарами: `o-` для об'єктів, `c-` для компонентів, `u-` для утиліт (`.c-product-card__title`).
* Порядок підключення в `main.scss` - *строго* від шару 1 до 7; специфічність має зростати зверху вниз («перевернутий трикутник»).
* `!important` дозволено *лише* в `utilities` (додати виняток у Stylelint для цієї папки).

==== Варіант 3. BEM + `@layer`

.Структура стилів
----
src/styles/
├── abstracts/      # змінні, функції, міксини
├── reset/          # → @layer reset
├── base/           # → @layer base
├── layout/         # → @layer layout
├── components/     # → @layer components (BEM-блоки)
├── utilities/      # → @layer utilities
└── main.scss
----

.main.scss
[source,scss]
----
@layer reset, base, layout, components, utilities;

@use 'reset' as *;       // усередині файлів шару: @layer reset { ... }
@use 'base' as *;
// ...
----

* Порядок шарів оголошується *один раз* на початку `main.scss`; кожен partial обгортає свої правила у відповідний `@layer`.
* Пріоритет визначається порядком шарів, а не специфічністю, - продемонструвати на захисті, що правило з `utilities` перемагає правило з `components` навіть за меншої специфічності.
* Стилі поза шарами (unlayered) не допускаються.
* Перевірити, що Browserslist проєкту підтримує `@layer` (`npx browserslist` + https://caniuse.com/css-cascade-layers[Can I use]).

==== Спільні вимоги для всіх варіантів

* Жодних `id` у селекторах, жодних селекторів за тегами всередині блоків (`.card h3`), вкладеність ≤ 3, без `!important` (крім utilities у варіанті 2).
* Блок не задає власних зовнішніх відступів і позиціонування - це робить батьківський блок через *мікс* (`class="product-card recommended__item"`).
* Stylelint: `selector-class-pattern` під BEM *з урахуванням префіксів свого варіанта*.
* У `README.md` - розділ «Архітектура стилів»: структура, правила іменування, пояснення порядку каскаду.

=== Завдання 3. Модульна сітка

. Реалізувати сітку макета на *CSS Grid* як окремий перевикористовуваний блок/об'єкт (`.l-grid`, `.o-grid` або `.grid` - залежно від варіанта): 2 / 6 / 12 колонок, gutter і поля - за таблицею вище, контент обмежений `max-width`.
. Параметри сітки - у дизайн-токенах; брейкпоінти - лише через міксин `mq()` з lab-09 (mobile first).
. Елементи сторінки розміщуються *по колонках сітки* (`grid-column: span N` / `grid-column: 3 / 11` тощо), а не довільними ширинами у пікселях.
Наприклад, у Bose на 744 картки «Recommended» займають 4 колонки по центру (зміщення на 1 колонку), а на 1260 - по 4 з 12.
. Зверніть увагу на *асиметричну галерею категорій*: широке й вузьке зображення чергуються (8 + 4 / 4 + 8 колонок на десктопі), на мобільному - 1 + 1 колонка.
. Повноширинні елементи (hero, нижній банер) виходять за межі сітки - на всю ширину viewport.
. *(Рекомендовано)* Додати режим налагодження сітки - модифікатор (наприклад, `.l-grid--debug`), що підсвічує колонки через `background: repeating-linear-gradient(...)` для звірки з макетом.

=== Завдання 4. Верстка сторінки

. Зверстати сторінку повністю у трьох ширинах макета; між ними верстка має коректно «тягнутися» (без горизонтального скролу, без накладання, з 320px до 1920px+).
На ширині понад 1260px контент центрується, повноширинні зображення - тягнуться.
. *Hero* та нижній банер - за правилами з фреймів `Image logic`:
** десктоп - `FILL WIDTH`, центрування по вертикалі; мобільний/планшет - `FILL HEIGHT`, кадр зсунутий так, як показано на макеті;
** реалізувати через `object-fit: cover` + `object-position` (а не `background-image`), щоб зберегти `<picture>`, `srcset` і `alt`;
** за потреби - *art direction* через `<source media="...">` (різний кадр для мобільного й десктопу).
. *Меню без JavaScript*: відкриття/закриття оверлея - через `<input type="checkbox">` + `<label>` (`:checked ~`) або `:target`.
Меню має виглядати як фрейми `Menu (…)` у кожній ширині; іконка бургера змінюється на «закрити».
Обов'язково: доступність з клавіатури, видимий фокус, `aria-label` для іконок-кнопок.
. *Стани* з макета (`Header Hovers`, `Buttons & inputs`): hover телефону з появою номера, hover бургера, кнопка default / hover / pressed (`:active`), поля вводу default / hover / `:focus-visible` / заповнене (`:not(:placeholder-shown)`).
Плюс `:focus-visible` для всіх інтерактивних елементів (у макеті його немає - продумати самостійно, у стилі макета).
. *Форма контактів*: семантичні `label` (можна візуально приховані), правильні `type`, `name`, `autocomplete`, `required`; валідація засобами HTML (`:user-invalid` / `:invalid` для оформлення).
Відправка не обов'язкова (`action` можна направити на заглушку).
. Телефон і email у блоці контактів та меню - активні посилання `tel:` / `mailto:`.
. Іконки - SVG (інлайн або спрайт через `<use>`), колір керується через `currentColor`.

=== Завдання 6. Якість: валідація та PageSpeed

. Перевірити опубліковану сторінку на https://validator.w3.org/[W3C Validator]: *0 помилок*.
Попередження - пояснити або виправити.
. Перевірити опубліковану сторінку на https://pagespeed.web.dev/[PageSpeed Insights] для *Mobile* і *Desktop*: усі чотири показники (Performance, Accessibility, Best Practices, SEO) - *у зеленій зоні (90–100)*.
. Скриншоти результатів обох перевірок (повністю, з видимою адресою сторінки) додати до `README.md`.

.Що зазвичай знижує бали PageSpeed
* Великі зображення без `srcset` / сучасних форматів, відсутні `width` і `height` (CLS).
* `loading="lazy"` на hero-зображенні (LCP) - для нього, навпаки, `fetchpriority="high"`.
* Шрифти без `font-display: swap`, зайві накреслення, відсутній `preconnect` / `preload`.
