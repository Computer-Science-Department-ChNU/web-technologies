## 1. Що таке HTML

**HTML** (HyperText Markup Language) — мова розмітки документів, з яких складаються вебсторінки. Це **не мова програмування**: вона не має змінних, умов чи циклів, а лише *описує структуру* вмісту.

HTML-файл можна створити в будь-якому текстовому редакторі. Рекомендуємо **VS Code** з вбудованим **Emmet** (наберіть `!` і натисніть `Tab` — отримаєте каркас документа).

**HTML5** — не лише нові теги, а й цілий набір API: Canvas, Geolocation, WebSocket, Web Storage, Web Workers тощо.

## 2. Структура HTML5-документа

```html
<!DOCTYPE html>
<html lang="uk">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="description" content="Короткий опис сторінки для пошуковиків">
  <title>Назва сторінки</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <!-- Весь видимий вміст сторінки -->
</body>
</html>
```

| Елемент | Призначення |
|---|---|
| `<!DOCTYPE html>` | Вмикає **Standards Mode**. Не тег, а інструкція браузеру |
| `<html lang="uk">` | Кореневий контейнер. Атрибут `lang` важливий для скрінрідерів, перекладачів і переносів |
| `<head>` | Службова інформація: метатеги, заголовок вкладки, підключення CSS/скриптів. **Не відображається** |
| `<meta charset="UTF-8">` | Кодування — без нього кирилиця може перетворитися на «кракозябри» |
| `<meta name="viewport">` | Правильне масштабування на мобільних — обов'язковий для адаптивних сайтів |
| `<title>` | Заголовок вкладки, назва в закладках і в пошуковій видачі |
| `<body>` | Все, що бачить користувач |

### Навіщо DOCTYPE?

- повідомляє браузеру, за якою специфікацією обробляти документ;
- вмикає **Standards Mode** замість **Quirks Mode** (емуляція браузерів 90-х з іншою box model та обробкою відсотків);
- без DOCTYPE поведінка CSS-верстки непередбачувана.

## 3. Анатомія тегу та правила розмітки

```html
<a href="https://chnu.edu.ua" target="_blank">Сайт університету</a>
│ │    └────────┬───────────┘                │                  │
│ └─атрибут     значення атрибута            вміст              закриваючий тег
└─відкриваючий тег
└──────────────────────────── елемент ──────────────────────────┘
```

- **Тег** — `<a>` і `</a>`. Деякі теги **непарні (void)**: `<img>`, `<br>`, `<hr>`, `<input>`, `<meta>`, `<link>`.
- **Атрибут** — додаткова інформація про елемент (`href`, `class`, `id`…).
- **Елемент** — усе від відкриваючого до закриваючого тегу включно.

### Правила

1. Елементи **не повинні перетинатися**:
   ```html
   <p><b>Правильно</b></p>
   <p><b>Неправильно</p></b>  <!-- ❌ -->
   ```
2. Блочні елементи можуть містити текст, рядкові та інші блочні елементи.
3. Рядкові елементи можуть містити текст та інші рядкові елементи.
4. Рядкові елементи **не можуть** містити блочні (виняток — `<a>` в HTML5 може обгортати блоки, якщо всередині немає інтерактивних елементів).
5. **Коментарі:** `<!-- текст коментаря -->` — не відображаються, але видимі в коді сторінки (не пишіть туди паролі!).

## 4. Блочні та рядкові елементи

| | **Блочні (block)** | **Рядкові (inline)** |
|---|---|---|
| Ширина | Вся доступна ширина батька | За вмістом |
| Новий рядок | Завжди починаються з нового рядка | Стоять в рядку поруч із текстом |
| `width`/`height` | Працюють | Не працюють |
| Приклади | `div`, `p`, `h1–h6`, `ul`, `ol`, `li`, `table`, `section`, `header` | `span`, `a`, `b`, `strong`, `em`, `i`, `img`*, `code` |

\* `<img>` — рядковий **заміщуваний** елемент, тому розміри для нього працюють.

> 💡 «Блочність» — це насправді CSS-властивість `display`. Будь-який елемент можна зробити блочним або рядковим через CSS (детальніше в лекціях 6–7).

## 5. Метатеги, SEO та Open Graph

**SEO** (Search Engine Optimization) — оптимізація сайту для пошукових систем.

```html
<head>
  <title>Кафедра комп'ютерних наук — ЧНУ</title>
  <meta name="description" content="Освітні програми, викладачі та новини кафедри">

  <!-- Open Graph: вигляд посилання у Facebook, Telegram, LinkedIn, Viber -->
  <meta property="og:title" content="Кафедра комп'ютерних наук">
  <meta property="og:description" content="Вступай до нас!">
  <meta property="og:image" content="https://example.com/preview.jpg">
  <meta property="og:url" content="https://example.com/">
  <meta property="og:type" content="website">

  <!-- Twitter / X має власні теги -->
  <meta name="twitter:card" content="summary_large_image">
</head>
```

- **Open Graph** розроблено Facebook; його використовують Facebook, LinkedIn, Telegram, Viber, Slack тощо.
- **Twitter/X** має аналогічні теги `twitter:card`, `twitter:title` тощо.

> 📄 Приклад: [03-open-graph.html](examples/00-markup/03-open-graph.html)
>
> 🧪 Перевірити, як виглядатиме ваше посилання: [opengraph.xyz](https://www.opengraph.xyz/).

## 6. Семантичні теги розділів сторінки

**Семантика** — розмітка, у якій тег відповідає *змісту* вмісту, а не його вигляду.

### Навіщо?

- ♿ **Доступність** — скрінрідери коректно озвучують структуру та дозволяють «стрибати» між розділами;
- 🔍 **SEO** — пошукові роботи краще розуміють ієрархію контенту;
- 🛠 **Підтримка коду** — `<header>` зрозуміліший, ніж `<div class="header">`;
- 🧹 **Чистота коду** — менше зайвих класів.

### Карта розділів сторінки

```
┌─────────────────── <header> ───────────────────┐
│  логотип            <nav> меню </nav>          │
├────────────────────── <main> ─────────┬────────┤
│  <article>                            │<aside> │
│    <header> заголовок статті </header>│ сайдбар│
│    <section> розділ 1 </section>      │ реклама│
│    <section> розділ 2 </section>      │        │
│    <footer> автор, дата </footer>     │        │
│  </article>                           │        │
├────────────────────── <footer> ───────┴────────┤
│  контакти, копірайт                            │
└────────────────────────────────────────────────┘
```

| Тег | Призначення |
|---|---|
| `<header>` | Шапка сторінки **або** секції: логотип, заголовок, часто навігація |
| `<nav>` | Блок основних навігаційних посилань: меню, «хлібні крихти», пагінація, зміст |
| `<main>` | Основний унікальний вміст. **Лише один** видимий `<main>` на сторінці |
| `<article>` | Самодостатній блок, який має сенс окремо: стаття, пост, коментар, картка товару |
| `<section>` | Тематична група вмісту **з власним заголовком** |
| `<aside>` | Побічний вміст: сайдбар, врізка, реклама |
| `<footer>` | Підвал сторінки або секції: контакти, копірайт, автор |

### Як обрати: `article`, `section` чи `div`?

```
Чи має вміст сенс сам по собі (можна опублікувати окремо)?
 ├─ Так → <article>
 └─ Ні → Чи це тематичний розділ із заголовком?
          ├─ Так → <section>
          └─ Ні → <div> (лише для стилізації/групування)
```

## 7. Текстова семантика

| Тег | Призначення |
|---|---|
| `<h1>`–`<h6>` | Заголовки за рівнем важливості. **Один `<h1>`** на сторінку — рекомендована практика; не пропускайте рівні |
| `<p>` | Абзац |
| `<blockquote>` / `<q>` | Блокова / рядкова цитата |
| `<strong>` / `<em>` | **Важливість** / *наголос* (семантично) |
| `<b>` / `<i>` | Лише візуальне виділення без додаткового змісту |
| `<mark>` | Виділення релевантного фрагмента (напр., у результатах пошуку) |
| `<time datetime="2026-09-01">` | Машинозчитувана дата/час |
| `<abbr title="...">` | Абревіатура з розшифровкою |
| `<code>`, `<pre>` | Фрагмент коду / форматований текст зі збереженням пробілів |
| `<sub>`, `<sup>` | Нижній / верхній індекс: H<sub>2</sub>O, x<sup>2</sup> |
| `<br>`, `<hr>` | Перенос рядка / тематичний розділювач |


## 8. Списки

### Невпорядкований `<ul>` (unordered list)

```html
<ul>
  <li>HTML</li>
  <li>CSS</li>
</ul>
```

Атрибут `type` (застарілий, краще через CSS `list-style-type`): `disc` ●, `circle` ○, `square` ■, `none`.

### Впорядкований `<ol>` (ordered list)

```html
<ol type="I" start="3" reversed>
  <li>Третій</li>
  <li>Другий</li>
</ol>
```

| Атрибут | Значення |
|---|---|
| `type` | `1` (за замовч.), `A`, `a`, `I`, `i` |
| `start` | З якого номера починати |
| `reversed` | Зворотна нумерація |

### Вкладені списки

Вкладений список розміщується **всередині `<li>`**, а не безпосередньо в `<ul>`:

```html
<ul>
  <li>Frontend
    <ul>
      <li>HTML</li>
      <li>CSS</li>
    </ul>
  </li>
</ul>
```

### Список визначень `<dl>`

```html
<dl>
  <dt>HTML</dt>
  <dd>Мова розмітки гіпертексту</dd>
  <dt>CSS</dt>
  <dd>Каскадні таблиці стилів</dd>
</dl>
```

> 📄 Приклади: [01_tag_ol.html](examples/02-lists/01_tag_ol.html), [02_tag_ul.html](examples/02-lists/02_tag_ul.html), [03_nested-list.html](examples/02-lists/03_nested-list.html), [04_tag_dl.html](examples/02-lists/04_tag_dl.html)

## 9. Таблиці

> ⚠️ Таблиці — **лише для табличних даних** (розклад, прайс, статистика). Верстати каркас сторінки таблицями — практика 2000-х; сьогодні для цього є Flexbox і Grid.

```html
<table>
  <caption>Розклад занять</caption>
  <thead>
    <tr>
      <th>День</th>
      <th>Пара</th>
      <th>Дисципліна</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td rowspan="2">Понеділок</td>
      <td>1</td>
      <td>Вебтехнології</td>
    </tr>
    <tr>
      <td>2</td>
      <td>Бази даних</td>
    </tr>
    <tr>
      <td>Вівторок</td>
      <td colspan="2">Самостійна робота</td>
    </tr>
  </tbody>
</table>
```

| Тег | Призначення |
|---|---|
| `<table>` | Контейнер таблиці |
| `<caption>` | Назва таблиці (одразу після `<table>`) |
| `<thead>` / `<tbody>` / `<tfoot>` | Логічні групи рядків: шапка / тіло / підсумок |
| `<tr>` | Рядок (table row) |
| `<th>` | Заголовна комірка — жирна й по центру за замовчуванням |
| `<td>` | Звичайна комірка (table data) |

| Атрибут | Дія |
|---|---|
| `colspan="N"` | Об'єднати N **стовпців** (по горизонталі) |
| `rowspan="N"` | Об'єднати N **рядків** (по вертикалі) |

**Застарілі атрибути `<table>`** (зустрічаються в старому коді, сьогодні замінюються CSS):

| Атрибут | CSS-заміна |
|---|---|
| `border` | `border` |
| `cellpadding` (відступ всередині комірки) | `padding` для `td, th` |
| `cellspacing` (відступ між комірками) | `border-spacing` / `border-collapse` |
| `bgcolor`, `background` | `background` |
| `align` | `text-align` / `margin` |

**Порожні комірки:** якщо комірка мусить бути порожньою, поставте `&nbsp;` (non-breaking space — нерозривний пробіл, що не дає браузеру переносити рядок у цьому місці).

> 🧮 **Лайфхак для `colspan`/`rowspan`:** перед версткою намалюйте таблицю на папері в клітинку. Сума «ширин» комірок у кожному рядку має бути однаковою.

> 📄 Приклади: [01-table/](examples/01-table/) (від `01_tag_table.html` до `15_attr_align.html`)

## 10. Зображення: img та picture

```html
<img src="images/cat.webp" alt="Рудий кіт спить на підвіконні"
     width="800" height="600" loading="lazy">
```

| Атрибут | Призначення |
|---|---|
| `src` | Шлях до файлу (jpg, png, webp, avif, svg, gif) |
| `alt` | Альтернативний текст — **обов'язковий**. Показується, якщо картинка не завантажилась; його читають скрінрідери. Для декоративних зображень — `alt=""` |
| `width`, `height` | Розміри в px. Вказуйте **завжди**: браузер заздалегідь резервує місце й сторінка не «стрибає» (метрика **CLS** — Cumulative Layout Shift) |
| `loading="lazy"` | Відкладене завантаження — для зображень нижче першого екрана |
| `fetchpriority="high"` | Підказка браузеру завантажити ресурс першочергово (покращує **LCP** — Largest Contentful Paint) |
| `title` | Спливаюча підказка при наведенні |

### `<picture>` — браузер сам обирає варіант

```html
<picture>
  <!-- 1. Сучасні формати з fallback -->
  <source srcset="hero.avif" type="image/avif">
  <source srcset="hero.webp" type="image/webp">
  <!-- 2. Art direction: інше кадрування на мобільних -->
  <source srcset="hero-mobile.jpg" media="(max-width: 600px)">
  <!-- 3. Обов'язковий fallback -->
  <img src="hero.jpg" alt="Студенти на лекції" width="1200" height="600">
</picture>
```

Сценарії: **адаптивність** (різні розміри під різні екрани), **art direction** (інше кадрування — крупний план замість загального), **сучасні формати з fallback**.

## 11. Гіперпосилання та шляхи

```html
<a href="https://chnu.edu.ua" target="_blank" rel="noopener noreferrer">ЧНУ</a>
<a href="about.html">Про нас</a>
<a href="#contacts">До контактів</a>              <!-- якір на id="contacts" -->
<a href="mailto:dean@example.com">Написати</a>
<a href="tel:+380501234567">Зателефонувати</a>
<a href="files/plan.pdf" download>Завантажити план</a>
```

| Атрибут | Призначення |
|---|---|
| `href` | Адреса посилання |
| `target="_blank"` | Відкрити в новій вкладці |
| `rel="noopener noreferrer"` | Безпека для зовнішніх посилань з `_blank` |
| `title` | Підказка |
| `download` | Завантажити файл замість відкриття |

### Абсолютні та відносні шляхи

- **Абсолютний:** `https://example.ua/images/logo.png` — повна адреса.
- **Відносний** — від поточного файлу:

| Запис | Значення |
|---|---|
| `page.html` або `./page.html` | Файл у поточній папці |
| `images/logo.png` | Файл у підпапці `images` |
| `../index.html` | Піднятися на рівень вище |
| `../../css/style.css` | Піднятися на два рівні вище |
| `/about.html` | Від кореня сайту |

```
project/
├── index.html          ← звідси: "pages/about.html", "img/logo.png"
├── img/logo.png
└── pages/
    └── about.html      ← звідси: "../index.html", "../img/logo.png"
```

> ⚠️ **Типова помилка:** шляхи на кшталт `C:\Users\Student\Desktop\img.png` — працюють лише на вашому комп'ютері. Використовуйте відносні шляхи! І пам'ятайте: на серверах (Linux) `Logo.png` ≠ `logo.png`.

> 📄 Приклади: [04-links.html](examples/00-markup/04-links.html), [04-links-anchors.html](examples/00-markup/04-links-anchors.html)

## 12. Валідація коду

**Валідний HTML** — код, що відповідає специфікації W3C/WHATWG. Помилки не завжди «ламають» сторінку (браузери дуже поблажливі), але вказують на проблеми з сумісністю, доступністю та SEO.

**Інструменти:**

- 🌐 [validator.w3.org](https://validator.w3.org/) — офіційний валідатор (за URL, файлом або вставкою коду);
- 🧹 **Лінтери** — HTMLHint, markuplint: перевірка під час розробки;
- 🔦 **Lighthouse** (Chrome DevTools) — аудит доступності, SEO та продуктивності;
- 🧩 **Плагіни VS Code** — перевірка в реальному часі;
- 🤖 **CI/CD** — автоматичний запуск валідатора на кожен pull request.

### Найчастіші помилки студентів

- ❌ немає `<!DOCTYPE html>`, `lang`, `charset`;
- ❌ відсутній `alt` у `<img>`;
- ❌ однаковий `id` у кількох елементах;
- ❌ `<li>` поза `<ul>`/`<ol>`;
- ❌ блочний елемент усередині `<p>` (`<p><div>…</div></p>`);
- ❌ незакриті або перехрещені теги;
- ❌ `<h1>` → одразу `<h4>` (пропущені рівні заголовків).

## Підсумки

- HTML5-документ має чітку структуру: `DOCTYPE → html → head + body`.
- DOCTYPE вмикає режим стандартів.
- Блочні/рядкові елементи — це передусім CSS-модель відображення (`display`).
- Метатеги впливають на SEO і на вигляд посилань у соцмережах (Open Graph).
- Семантичні теги покращують доступність, SEO та підтримуваність коду.
- Валідність перевіряється вручну (W3C Validator) та автоматизовано (лінтери, CI/CD).

## 🎯 Практичне завдання

Зверстайте сторінку «Моє резюме» лише семантичними тегами (без жодного `div`):

- `<header>` з іменем та фото (`<img>` з `alt`, `width`, `height`);
- `<nav>` з якірними посиланнями на розділи;
- `<main>` з `<section>`-ами: «Про мене», «Навички» (вкладений список), «Освіта» (таблиця з `colspan`/`rowspan`), «Контакти» (`mailto:`, `tel:`);
- `<footer>` з `<time>` останнього оновлення;
- метатеги Open Graph.
